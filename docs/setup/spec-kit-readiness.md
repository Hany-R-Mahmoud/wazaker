# Spec-Kit Readiness

## Purpose

This document marks the handoff from the operating-system work to phase 4 feature execution.

## Why Spec-Kit Was Not The Right Tool For Phases 1 To 3

The recent work was infrastructure and operating-system work:

- local automation setup
- repo workflow automation
- team routing model
- guarded delivery mechanics

`spec-kit` is strongest when the work is feature delivery rather than platform setup.

## When Spec-Kit Becomes The Default

Use `spec-kit` once a feature is being prepared for product delivery.

Recommended phase 4 sequence:

1. `speckit-clarify`
2. `speckit-specify`
3. `speckit-plan`
4. `speckit-tasks`
5. `speckit-analyze`
6. implementation through the guarded delivery pipeline

## Entry Criteria

Phase 4 can begin when:

- the automation operating model is documented
- the agent operating model is documented
- the guarded delivery pipeline exists
- the next feature candidate has a real product question worth clarifying

## First Recommended Phase 4 Targets

- selected passage flow
- recording shell
- mock feedback shell
- bilingual recitation session structure
